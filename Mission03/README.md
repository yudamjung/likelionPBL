## 🦁 멋쟁이사자처럼 프론트엔드 PBL

### Mission 03. JavaScript 기초: 버튼 클릭 시 사자 명단이 추가되는 동적 효과

#### 과제 목표

- 버튼 클릭과 폼 제출 같은 사용자 동작이 발생했을 때, **어떤 흐름으로 코드가 실행되고 화면이 바뀌는지** 설명할 수 있다.
- 필요한 요소를 찾기 위해 DOM을 선택하고, 새 HTML 요소를 만들어 추가하거나 삭제하는 과정에서 사용되는 기본 조작을 설명할 수 있다.
- 입력 폼을 구성하면서, **입력값이 어디에서 들어오고, 어디로 모이며, 어디에 반영되는지**와 그 흐름을 설명할 수 있다.
- 화면에 보여줄 정보를 **배열, 객체 형태의 데이터로 정리하고, 그 데이터를 기준으로 UI를 구성한 방법과 설계 이유**를 설명할 수 있다.
- 기능이 늘어나도 코드가 무너지지 않도록, **변수, 함수로 역할을 나누어 정리한 기준과 이유**를 설명할 수 있다.

> 목표 수행 시간 : 30시간
> 

#### 구현 지침

1. 제출물 및 실행
    1. 제출물은 정적 웹페이지 1개이며, 브라우저에서 html 파일을 직접 열어도 정상적으로 렌더링된다.
    2. 파일은 `index.html`, `style.css`, `script.js`로 구성된다.
    3. 모든 Javascript 코드는 `script.js`에 포함되며, HTML에서는 DOM이 준비된 뒤 실행되어야 한다.
2. 동적 페이지 전환
    1. 사용자 입력, 버튼 클릭에 따라 화면이 변하는 동적 동작을 포함한다.
    2. 명단 데이터가 바뀌면 화면도 함께 바뀌는 동작이 구현되어야 한다.
3. 명단 데이터 관리
    1. 아기 사자 명단은 JavaScript의 배열 / 객체 형태로 관리되어야 한다.
    2. 화면에 보이는 카드들은 이 명단 데이터와 항상 동기화되어야 한다. (명단 추가/삭제가 일어나면 요약 카드, 상세 카드도 추가/삭제 되고, 총 인원도 동시에 갱신된다)
4. 초기 화면 데이터 동기화
    1. 페이지 로드 시, (2주차에 작성해 둔) 기존 HTML에 이미 존재하는 카드들을 읽어 명단 데이터로 초기화한다.
    2. 초기화가 끝나면 `총 n명` 텍스트가 현재 명단 수로 자동 갱신되어야 한다.
5. 컨트롤 영역 인터랙션
    1. 상단 컨트롤 영역에는 다음 요소가 존재하며, 명시된 동작이 정상적으로 작동해야 한다.
        1. `아기 사자 추가` 버튼: 입력 폼 영역을 열고 닫는다. (토글)
            1. 입력 폼 영역은 초기 상태에서 숨겨져 있어야 한다.
    2. `마지막 아기 사자 삭제` 버튼: 명단의 마지막 항목을 삭제하고, 화면에서도 제거한다.
    3. `총 n명` 표시: 명단의 길이에 맞춰 항상 갱신된다.
6. 폼 제출로 명단 추가
    1. 추가하기 클릭 시 입력값을 읽어 새 아기 사자 데이터를 생성한다.
    2. 비어 있는 입력값이 있으면 추가가 수행되지 않으며, 비어 있는 input 아래에 경고 메시지가 표시된다.
    3. 파트의 경우 Frontend / Backend / Design 중에 한 가지를 드롭다운으로 선택하도록 구현한다.
    4. **관심 기술 입력값은 쉼표를 기준으로 분리된다.**
        1. 그 중 첫 번째 값이 요약 카드의 배지로 등장한다.
        2. 상세 자기소개 정보 영역에서도 불렛포인트로 알맞게 분리되어 표시되어야 한다.
    5. **추가가 성공하면 아래 동작이 모두 수행되어야 한다.**
        1. 명단 데이터에 새 항목이 추가된다.
        2. 요약 카드가 그리드 마지막 부분에 생성되어 추가된다.
        3. 상세 카드가 목록 마지막 부분에 생성되어 추가된다.
        4. `총 n명` 값이 갱신된다.
        5. 폼이 닫히고 입력값이 초기화된다.
7. 마지막 항목 삭제로 명단 제거
    1. `마지막 아기 사자 삭제` 버튼 클릭 시, 명단의 마지막 항목이 제거된다.
    2. **제거 시 아래가 모두 수행되어야 한다.**
        1. 명단 배열에서 마지막 항목이 삭제된다.
        2. 해당 항목의 요약 카드와 상세 카드 DOM 요소가 함께 삭제된다.
        3. `총 n명` 값이 갱신된다.
    3. 명단이 비어 있을 때는 삭제 동작이 수행되지 않아야 한다.
8. 입력 폼 반응형 레이아웃
    1. 입력 폼 중 일부 항목은 2열로 배치되도록 구현하고, 일부 항목은 전체 너비를 차지하도록 구성한다.
    2. 화면 너비가 작아지는 경우 폼 레이아웃은 전체 1열로 전환되며, 기존에 2열로 배치되던 항목들도 세로로 자연스럽게 쌓여야 한다.

#### 제약 사항

1. **언어 / 실행 환경**
    - HTML, CSS, JavaScript을 사용해 구현한다.
    - 웹 브라우저에서 실행되는 정적 웹 페이지여야 한다.
    - 별도의 웹 서버, 빌드 도구, 개발 서버는 사용하지 않는다.
    - TypeScript를 사용하지 않는다.
2. **기능 범위**
    - Javascript는 DOM 이벤트 처리와 DOM 조작 (추가/삭제/표시 갱신) 범위에서만 사용한다.
    - 데이터는 브라우저 메모리에서만 관리하며, 새로고침하면 초기 상태로 돌아가도 된다.
    - 서버 통신 (fetch), 데이터 저장 (localStorage/DB), 로그인 등 외부 시스템 연동 기능은 구현하지 않는다.
3. **라이브러리 및 프레임워크 사용 범위**
    - CSS 프레임워크 (Bootstrap, Tailwind CSS 등)는 사용하지 않는다.
    - JavaScript 라이브러리/프레임워크 (React, Vue, jQuery 등)는 사용하지 안않는다.
    - UI 관련 라이브러리는 사용하지 않는다.
    - 외부 CSS/JS 파일이나 CDN을 불러오지 않고, 모든 파일은 직접 작성한다.
    - 패키지 매니저 (npm, yarn, pnpm 등)는 사용하지 않는다.
4. **스타일 작성 방식**
    - 모든 스타일은 직접 작성한 CSS 코드로 구현한다.
    - 인라인 스타일(`style` 속성) 은 사용하지 않는다.
    - 스타일은 별도의 CSS 파일로 관리해야 한다.
    - 애니메이션 효과나 테마 전환 등 기능 요구 사항 외의 시각적 연출을 위한 추가 기능은 구현하지 않는다.
5. **JavaScript 작성 방식**
    - 이벤트 등록은 `addEventListener` 를 사용하고, HTML에 `onclick` 같은 인라인 이벤트는 사용하지 않는다.
    - 인라인 스크립트는 사용하지 않는다.
    - 별도의 JavaScript 파일을 관리하고, 해당 파일에 모든 JavaScript 코드가 작성되어 있어야 한다.
6. **프로젝트 구성 범위**
    - `index.html`, `style.css`, `script.js` 3개 파일로 구성한다.
    - 추가 이미지/폰트 파일은 선택 사항이며, 없어도 실행 가능해야 한다.
        - 추가 이미지/폰트 파일이 필요할 경우 루트 디렉토리에 `assets` 폴더를 만들고, 모든 파일을 하위에 위치시킨다.
