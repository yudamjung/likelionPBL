# Mission 03 개발일지

## 트러블슈팅 — 폼 입력값을 배열에 추가하고, 삭제 버튼으로 마지막 사자를 지우는 기능

### 문제 상황

'아기 사자 추가' 폼에 정보를 입력해 제출하면 카드가 늘어나고, '마지막 아기 사자 삭제' 버튼을 누르면 마지막 카드가 사라지도록 만들던 중 다음 문제들이 발생했다.

1. 삭제 버튼을 누르면 "총 N명"의 숫자는 줄어드는데 **화면의 카드는 그대로 남아 있었다.**
2. 폼을 제출하면 숫자만 늘어나고 `lions` 배열에는 아무것도 추가되지 않았다. 그래서 추가한 뒤 삭제를 누르면 숫자와 배열의 길이가 서로 어긋났다.
3. 사자가 0명인 상태에서 삭제 버튼을 계속 누르면 **-1명, -2명**처럼 인원수가 음수가 되었다.
4. 폼으로 추가한 사자는 관심 기술을 3개 미만으로 입력하면 상세 카드에 `undefined`가 출력되었다.

---

### 원인

#### 1. 데이터를 바꾸는 코드와 화면을 그리는 코드가 분리되어 있었다

카드는 페이지가 로드될 때 `forEach`로 **딱 한 번만** 그려졌다. 삭제 버튼의 이벤트 핸들러는 `lions.pop()`으로 배열만 바꿀 뿐, 이미 그려진 `.baby-lion-card`와 `.detail-card`는 건드리지 않았다.

```js
deleteLion.addEventListener("click", (e) => {
    count--;
    lions.pop();                 // 배열은 바뀌지만
    headCount.innerHTML = count; // 화면에서는 숫자만 바뀐다 (카드는 그대로)
});
```

배열이 바뀌어도 DOM은 자동으로 따라 바뀌지 않는다. JS가 직접 DOM을 다시 그려야 한다.

#### 2. 같은 값을 두 군데에서 따로 관리했다 (`count` 와 `lions.length`)

인원수를 `let count = lions.length;`로 따로 저장해 두고 `count++`, `count--`로 직접 조작했다. 그러다 보니 폼 제출에서는 `count++`만 하고 `lions.push()`를 빼먹어도 아무 에러 없이 둘이 어긋났다.

```js
form.addEventListener("submit", (event) => {
    event.preventDefault();
    count++;                     // 숫자만 올라가고 lions에는 추가되지 않음
    headCount.innerHTML = count;
});
```

또한 빈 배열에서 `pop()`은 에러 없이 `undefined`를 반환하기 때문에, `count--`만 계속 실행되어 음수가 되었다.

#### 3. 관심 기술 출력이 인덱스에 고정되어 있었다

상세 카드가 `techStack[0]`, `techStack[1]`, `techStack[2]`를 직접 꺼내 쓰고 있었다. 폼에서 기술을 2개만 입력하면 `techStack[2]`가 `undefined`이므로 화면에 그대로 `undefined`가 출력되었다.

---

### 해결 방법

#### 1. "배열을 바꾼다 → 다시 그린다"를 하나의 흐름으로 묶었다

카드를 그리는 코드를 `renderCards()` 함수로 묶었다. 이 함수는 두 카드 영역을 **먼저 비운 뒤** `lions` 배열 전체를 다시 그린다. 비우지 않으면 `innerHTML +=`로 기존 카드 뒤에 계속 쌓여 카드가 중복된다.

```js
function renderCards() {
    cardLayoutArea.innerHTML = '';
    detailProfileCardArea.innerHTML = '';

    lions.forEach((lion) => {
        // ... 카드 HTML 생성
    });

    headCount.textContent = lions.length;
}
```

이제 추가와 삭제 모두 **배열을 바꾸고 `renderCards()`를 한 번 호출**하면 끝난다.

#### 2. `count` 변수를 없애고 `lions.length` 하나만 사용했다

인원수는 `renderCards()` 안에서 `lions.length`로 바로 구한다. 같은 정보를 저장하는 곳이 하나뿐이라 서로 어긋날 수 없다.

#### 3. 폼 제출 시 입력값으로 객체를 만들어 `push()` 했다

각 입력 요소에 `id`를 붙이고, 제출 시 그 값을 읽어 `lions`의 다른 항목과 같은 구조의 객체로 만들었다.

```js
form.addEventListener("submit", (event) => {
    event.preventDefault(); // 새로고침을 막아야 lions 배열과 화면이 유지된다

    const newLion = {
        name: document.querySelector("#lion-name").value.trim(),
        role: document.querySelector("#part-name").value,
        description: document.querySelector("#lion-description").value.trim(),
        profileImgLink: '', // 폼에 이미지 입력란이 없으므로 비워 두고, 렌더링 시 기본 이미지로 대체
        contacts: {
            email: document.querySelector("#lion-email").value.trim(),
            phone: document.querySelector("#lion-phone").value.trim(),
            web: document.querySelector("#lion-web").value.trim()
        },
        techStack: document.querySelector("#lion-tech-stack").value
            .split(',')
            .map((tech) => tech.trim())
            .filter(Boolean)
            .slice(0, 3),
        catchphrase: document.querySelector("#lion-catchphrase").value.trim()
    };

    lions.push(newLion);
    renderCards();

    form.reset();
    form.classList.remove("show");
});
```

- 관심 기술은 `"JS, CSS , HTML"` 같은 문자열을 `split(',')` → `trim()` → 빈 항목 제거(`filter(Boolean)`) → 최대 3개(`slice(0, 3)`)로 가공해 배열로 저장했다.
- 이미지가 없는 사자는 `DEFAULT_PROFILE_IMG` 상수로 대체하도록 자리를 만들어 두었다.
- 관심 기술을 3개까지만 받기로 했으므로 `slice(0, 3)`으로 저장 시점에 개수를 제한했고, 출력은 `map`으로 저장된 항목만큼 그리게 했다.

#### 4. 삭제 버튼에 빈 배열 방어 코드를 넣었다

```js
deleteLion.addEventListener("click", () => {
    if (lions.length === 0) return; // 지울 사자가 없으면 아무것도 하지 않는다

    lions.pop();
    renderCards();
});
```

#### 5. 사용자 입력을 `innerHTML`에 넣기 전에 이스케이프했다

폼에 입력한 문자열이 `innerHTML`로 들어가므로, 입력값에 `<script>` 같은 태그가 있으면 그대로 HTML로 해석될 수 있다. `escapeHtml()` 함수로 `& < > " '`를 치환해 입력한 내용이 글자 그대로 표시되도록 했다.

---

### 결과

- 추가: 폼 제출 → `lions`에 객체 추가 → 카드와 "총 N명"이 함께 갱신된다.
- 삭제: `lions`의 마지막 항목 제거 → 카드와 "총 N명"이 함께 줄어든다.
- 0명일 때 삭제를 눌러도 인원수가 음수가 되지 않는다.
- 데이터(`lions`)와 화면이 항상 일치한다.

---

### 배운 점

- **배열을 바꾼다고 화면이 자동으로 바뀌지 않는다.** 바닐라 JS에서는 데이터를 바꾼 뒤 화면을 다시 그리는 코드를 직접 호출해야 한다.
- **같은 정보를 두 곳에 저장하지 않는다.** `count`처럼 `lions.length`로 구할 수 있는 값을 따로 저장하면 어긋날 가능성이 생긴다. 하나만 두고 거기서 계산하는 편이 안전하다.
- **`pop()`은 빈 배열에서도 에러를 내지 않는다.** 에러가 나지 않는 만큼 오히려 조용히 잘못된 상태가 되므로, 호출 전에 길이를 확인해야 한다.
- **`innerHTML +=`는 기존 내용을 유지한 채 이어 붙인다.** 다시 그릴 때는 먼저 `innerHTML = ''`로 비워야 중복되지 않는다.
- **인덱스를 고정해서 꺼내 쓰면(`techStack[2]`) 데이터 개수가 달라질 때 깨진다.** 반복문이나 `map`으로 있는 만큼만 출력하는 편이 안전하다.
- **사용자 입력을 `innerHTML`에 넣을 때는 이스케이프가 필요하다.**
- `form`의 `submit` 이벤트에서는 `event.preventDefault()`를 호출해야 페이지가 새로고침되며 데이터가 사라지는 일을 막을 수 있다.

## 설계 판단 — 초기 데이터를 HTML 카드에서 읽지 않고 JS 배열을 기준으로 둔 이유

### 지침과 다르게 구현한 부분

구현 지침 4번은 페이지 로드 시 2주차에 작성한 **HTML의 기존 카드를 읽어 명단 데이터로 초기화**하라고 안내한다. 이 과제에서는 반대로 `script.js`의 `lions` 배열에 초기 데이터를 직접 작성하고, 그 배열로 카드를 그리는 방식을 선택했다. 따라서 `index.html`의 카드 영역은 비어 있고, 지침 4번의 "HTML 카드를 읽어 초기화"는 따르지 않았다. (초기화 후 `총 n명`이 현재 명단 수로 자동 갱신되는 부분은 충족한다.)

### 그렇게 판단한 이유

HTML 카드를 읽어 오는 방식으로 바꾸면 아래와 같은 부담이 생긴다고 판단했다.

1. **같은 정보가 두 군데에 생긴다.** 카드 구조가 `index.html`의 마크업과 `renderCards()`의 템플릿에 모두 존재하게 된다. 카드 디자인을 바꾸거나 항목을 추가할 때 두 곳을 함께 고쳐야 하고, 한쪽을 놓치면 초기 카드와 새로 추가된 카드의 모양이 달라진다.
2. **읽는 코드가 깨지기 쉽다.** 요약 카드에는 이미지·배지가, 상세 카드에는 연락처·관심 기술이 나뉘어 있어서 두 카드를 순서(인덱스)로 짝지어 합쳐야 한다. 두 영역의 순서가 하나라도 어긋나면 다른 사자의 정보가 섞인다. 또한 `Email:`, `Phone:` 같은 라벨 텍스트가 섞인 `<li>`에서 값만 뽑으려면 별도의 파싱이 필요하다.
3. **코드가 늘어난다.** 9명 분량의 카드 마크업을 HTML에 직접 작성하고, 이를 읽어 객체로 바꾸는 `loadLionsFromDom()`도 새로 만들어야 한다.
4. **데이터의 출처가 하나일 때 동기화가 쉽다.** 지금은 `lions` 배열이 유일한 기준이고, 추가·삭제 모두 "배열 변경 → `renderCards()` 호출"만 거치면 화면이 항상 데이터와 일치한다. 초기 데이터도 같은 배열에서 같은 함수로 그려지므로, 초기 화면과 이후에 추가된 카드가 항상 같은 구조를 가진다.

### 트레이드오프

- 지침 4번의 문구를 그대로 구현한 것은 아니므로, 평가 기준에서는 해당 항목이 미충족으로 보일 수 있다.
- HTML 파일만 열어 보면 카드가 비어 있고, JS가 실행되어야 카드가 보인다. (과제 제약상 JS는 허용되는 범위이며 `defer`로 DOM이 준비된 뒤 실행된다.)
- 지침을 그대로 따르려면 위의 변경(카드 마크업을 HTML에 작성 + 읽어서 `lions` 초기화)이 필요하다. 요구사항 충족이 우선인 상황이라면 그 방식으로 바꿀 수 있다.

## 회고

처음에는 "삭제 버튼을 누르면 배열에서 빠지고 숫자도 줄어드니 잘 동작한다"고 생각했다. 하지만 실제로 확인해 보니 화면에 보이는 것과 배열이 가진 데이터는 별개였고, 두 가지를 따로 관리하는 순간 어긋날 수 있다는 것을 알게 되었다. 앞으로는 데이터가 바뀌는 모든 경로(추가, 삭제)가 같은 렌더링 함수를 거치도록 만들어, 화면이 항상 데이터를 그대로 반영하게 하는 방식으로 설계하려 한다.
