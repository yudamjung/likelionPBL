## 🦁 멋쟁이사자처럼 프론트엔드 PBL
### Mission 02. CSS 기초: CSS 레이아웃으로 아기사자 명단 대시보드 만들기

#### 과제 목표
- Flexbox와 Grid의 차이를 바탕으로, "요소 내부 정렬"과 "여러 요소 배치"에서 어떤 방식을 선택했는지 근거를 들어 설명할 수 있다.
- 화면 크기 조건에 따라 레이아웃 규칙을 분기해 적용하는 방법을 설명할 수 있다.
- 고정된 좌표로 화면을 맞추기보다, 흐름(Flow)과 레이아웃 속성으로 안정적인 구조를 만드는 방식의 장점을 설명할 수 있다.
- 카드 UI가 반복되는 상황에서, 반복 가능한 HTML 구조(공통 구조/변하는 데이터)를 어떻게 설계했는지 설명할 수 있다.
- 같은 요소에 스타일 규칙이 겹칠 때, 어떤 규칙이 적용되는지와 그 이유를 설명할 수 있다.
- 컴포넌 내부에서 특정 요소를 원하는 위치에 배치할 때, position을 언제/왜 사용하는지 설명할 수 있다.

> 목표 수행 시간 : 20시간

#### 구현 지침
1. 제출물 및 실행
    1. 제출물은 정적 웹페이지 1개이며, 브라우저에서 html 파일을 직접 열어도 정상적으로 렌더링된다.
    2. 파일은 `index.html`과 `style.css`로 구성된다.
    3. Javascript 파일이나 코드가 포함되지 않는다.
2. HTML 구조
    1. 페이지를 구성하는 요소들에 적절한 HTML 태그가 사용되어, HTML 문서만을 통해서 해당 영역이 어떠한 역할을 하는지 파악 가능해야 한다.
    2. 각 태그는 스타일을 적용하기 위한 목적이 아니라, 콘텐츠의 역할과 구조를 기준으로 선택되어야 한다.
    3. 불필요한 `div`의 중첩은 지양한다.
3. 스타일 분리 및 관리
    1. 모든 스타일은 별도의 CSS 파일에 작성되어야 한다.
    2. HTML 파일에는 스타일 관련 코드가 포함되어 있지 않아야 한다.
    3. 중복되는 스타일 선언은 최소화하고, 일관된 스타일 규칙을 유지한다.
    4. CSS 클래스명을 지을 때는 의미를 고려한다.
4. 정적 페이지 구성
    1. Javascript 코드는 작성하지 않는다.
    2. 사용자 입력, 버튼 클릭, 화면 전환 등 동적 동작은 포함하지 않는다.
    3. 페이지를 새로고침해도 화면 구성은 변하지 않는다.
5. 요약 카드 목록 영역
    1. 요약 카드는 여러 개 (9개 이상 권장) 반복되어 표시된다.
    2. 모든 요약 카드는 동일한 구조/형태의 카드 UI로 구성되어 있다.
    3. 요약 카드들은 그리드 형태로 정렬되어 목록처럼 보인다.
6. 배지 표시
    1. 모든 요약 카드에 배지 1개가 표시된다.
    2. 배지는 프로필 이미지 위에 겹쳐 보이는 오버레이 형태로 나타난다.
    3. 배지는 이미지 우측 상단에 고정된 위치로 표시된다.
    4. 브라우저 크기를 조정했을 때도, 배지는 이미지 내에서의 상대적인 위치를 흔들림 없이 유지한다.
    5. 배지 텍스트는 해당 인물의 상세 카드의 '관심 기술 목록' 첫 번째 항목과 동일하다.
7. '내 자기소개 카드' 강조 표시
    1. 요약 카드 중 1개는 '내 카드'로서, 다른 카드들과 명확히 구분되는 시각적 강조가 적용되어 있다.
    2. '내 카드'를 제외한 나머지 카드는 모두 동일한 스타일을 유지해야 한다.
    3. 강조는 카드 전체의 정보 구조를 바꾸지 않고, 스타일 차이로만 인지될 수준이어야 한다.
    4. 강조로 인해 카드의 크기/레이아웃 규칙이 달라져 다른 카드와의 정렬이 깨지면 안 된다.
8. 반응형 레이아웃
    1. 화면 너비에 따라 요약 카드의 열 개수가 변한다.
        1. **모바일: 1열**
        2. **태블릿/중간 화면: 2열**
        3. **데스크톱: 3열**
    2. 화면을 늘리거나 줄였을 때 카드가 서로 겹치거나 화면 밖으로 튀어나오지 않는다.
    3. 반응형 변화는 브라우저 너비 변경만으로 확인 가능하다.
9. 상세 자기소개 목록 영역
    1. 상세 카드는 요약 카드 수와 동일한 개수로 존재한다.
    2. 상세 카드는 1열 목록 형태로, 위에서 아래로 읽히게 배치되어 있다.
10. 레이아웃 구현 방식
    1. 카드 내부 요소들의 정렬은 Flexbox를 사용해 구현한다.
    2. 카드 외부 레이아웃은 고정 좌표에 의조낳지 않고 구성되어야 한다.
    3. 여백과 간격은 `margin`, `padding`, `gap` 등의 속성을 적절히 활용해 표현해야 한다.
    4. 특정 요소의 여백이나 크기 값을 변경했을 때, 해당 요소에 적용된 스타일만 변경되도록 구현되어야 한다.
    5. 레이아웃 조정을 위해 임의의 빈 요소나 불필요한 태그를 사용하지 않는다.

#### 제약 사항
1. 언어 / 실행 환경
- HTML과 CSS만을 사용해 구현한다.
- 웹 브라우저에서 실행되는 정적 웹 페이지여야 한다.
- 별도의 웹 서버, 빌드 도구, 개발 서버는 사용하지 않는다.
2. 기능 범위
- Javascript 파일은 생성하지 않는다.
- 사용자 입력, 버튼 클릭, 화면 전환 등 동적 동작을 구현하지 않는다.
- DOM 조작, 데이터 변경 로직은 포함하지 않는다.
3. 라이브러리 및 프레임워크 사용 범위
- CSS 프레임워크 (Bootstrap, Tailwind CSS 등)는 사용하지 않는다.
- UI 관련 라이브러리는 사용하지 않는다.
- 외부 CSS 파일이나 CDN을 불러오지 않고, 모든 파일은 직접 작성한다.
- 패키지 매니저 (npm, yarn, pnpm 등)는 사용하지 않는다.
4. 스타일 작성 방식
- 모든 스타일은 직접 작성한 CSS 코드로 구현한다.
- 인라인 스타일(`style` 속성) 은 사용하지 않는다.
- 스타일은 별도의 CSS 파일로 관리해야 한다.
- 애니메이션 효과나 테마 전환 등 시각적 연출을 위한 추가 기능은 구현하지 않는다.
5. 프로젝트 구성 범위
- 하나의 HTML 파일과 하나의 CSS 파일로 구성한다.
